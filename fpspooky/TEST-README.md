# 🧪 Тестовые скрипты для автовыдачи

Тестовые скрипты для проверки логики покупок с ником **chinoyouka1**.

---

## 📋 Доступные тесты

### 1. `quick-test.js` - Быстрый тест
**Самый простой тест для проверки одной покупки**

```bash
node quick-test.js
```

**Что тестирует:**
- ✅ Создание заказа
- ✅ Отправка приветствия
- ✅ Валидация ника `chinoyouka1`
- ✅ Подтверждение ника
- ✅ Проверка баланса
- ✅ Выдача валюты
- ✅ Завершение заказа

**Время выполнения:** ~5 секунд

---

### 2. `test-purchase.js` - Полный тест покупки
**Детальное тестирование всех этапов**

```bash
node test-purchase.js
```

**Что тестирует:**
- 📦 Создание заказа
- 📝 Установка текущего заказа
- 💬 Отправка сообщений
- 🎮 Валидация ника
- ✅ Подтверждение
- 💰 Проверка баланса
- 📋 Работа с очередью
- ⏭️ Обработка следующего заказа
- ✔️ Завершение заказа

**Время выполнения:** ~10 секунд

---

### 3. `test-scenarios.js` - Расширенные сценарии
**Тестирование различных ситуаций**

```bash
node test-scenarios.js
```

**Сценарии:**

#### 📦 Сценарий 1: Нормальная покупка
Полный цикл успешной покупки от начала до конца

#### ❌ Сценарий 2: Неверный ник
Тестирование валидации с различными невалидными никами:
- `ab` - слишком короткий
- `very_long_nickname_123456` - слишком длинный
- `nick with spaces` - с пробелами
- `ник_кириллица` - кириллица
- `nick@special` - спецсимволы

#### 💸 Сценарий 3: Недостаточно баланса
Проверка поведения при нехватке средств у бота

#### 📋 Сценарий 4: Очередь заказов
Тестирование системы очереди:
- Добавление в очередь
- Обработка по порядку
- Уведомления о позиции

#### ⏱️ Сценарий 5: Таймаут заказа
Симуляция истечения 2-минутного таймаута

#### 🔄 Сценарий 6: Отмена подтверждения
Проверка отмены и повторного запроса ника

**Время выполнения:** ~30 секунд

## 🔧 Настройка перед тестами

### 1. Убедитесь, что настроен `settings.txt`
```ini
[Bot]
username: ваш_ник_бота
anarchy: номер_анархии
orderName: что-то связанное с валютой
```

### 2. Замените тестовый ID (опционально)
В файлах тестов найдите:
```javascript
const BUYER_ID = '999999'; // Замените на реальный ID
```

### 3. Проверьте настройки автовыдачи
Файл `data/configs/delivery.json` должен содержать товар с названием, включающим `"что-то связанное с валютой"`.

### ❌ Возможные ошибки

**Ошибка подключения:**
```
Ошибка при отправке сообщения: fetch failed
```
→ Проверьте `golden_key` в `settings.txt`

**Ошибка валидации:**
```
Валидация: ❌ FAIL
```
→ Ник не соответствует формату `[A-Za-z0-9_]{3,16}`

**Недостаточно баланса:**
```
❌ НЕДОСТАТОЧНО БАЛАНСА!
   Требуется: 1,000,000
   Доступно: 0
```
→ Пополните баланс бота на сервере

## 🐛 Отладка

```javascript
global.settings.debug = true;
```

### Проверить текущий заказ
```javascript
console.log('Текущий заказ:', Order.getCurrent());
```

### Проверить очередь
```javascript
console.log('В очереди:', Order.getWaiting().length);
```

### Проверить баланс бота
```javascript
console.log('Баланс:', global.bot.balance);
```

---

## 📝 Примечания

1. **Тесты не создают реальные заказы** - они только симулируют логику
2. **Сообщения отправляются реально** - если указан валидный `golden_key`
3. **Баланс бота** берётся из реального состояния на сервере
4. **Очередь** очищается после каждого теста

## 🚀 Быстрый старт

```bash
# 1. Установите зависимости (если ещё не установлены)
npm install

# 2. Настройте settings.txt
# Убедитесь, что указан golden_key и настройки бота

# 3. Запустите быстрый тест
node quick-test.js

# 4. Если всё работает, запустите полные тесты
node test-scenarios.js
```

---

## ⚠️ Важно

- Тесты используют **реальное API FunPay** для отправки сообщений
- Не запускайте тесты слишком часто, чтобы избежать блокировки
- Тестовый ID `999999` может не существовать - сообщения не дойдут
- Для полноценного теста используйте реальный ID покупателя

---

## 📞 Поддержка

Если тесты не работают:
1. Проверьте `settings.txt`
2. Убедитесь, что бот запущен и авторизован на сервере
3. Проверьте баланс бота командой `/money`
4. Проверьте логи в консоли
